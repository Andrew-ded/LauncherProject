# Project Launcher

Лаунчер рабочих проектов для Windows. Все проекты лежат плашками на одном экране:

- клик по плашке открывает проект в его IDE (Rider, Visual Studio, VS Code, Android Studio);
- в правом верхнем углу видна текущая git-ветка;
- значок GitHub/GitLab показывает число открытых PR/MR и Issue, по клику открывается их список;
- у каждого проекта есть заметки «ключ → значение»: порт, команда запуска, где лежат конфиги;
- иконка папки открывает проводник, иконка терминала — терминал в папке проекта;
- на плитке проекта стоит иконка его платформы (Web, Windows, Android), если ты её загрузил, иначе — цветная монограмма;
- правая кнопка мыши даёт открыть проект в другой IDE, открыть терминал в папке, скопировать путь, изменить или убрать проект.

Проекты добавляются тремя способами:

- **импорт из общей папки** (иконка папки с лупой в шапке): указываешь папку вроде `D:\Work`, лаунчер просматривает её подпапки и предлагает добавить всё, что похоже на проект (`.sln`/`.csproj`, Gradle, `package.json`, `.git`…). Новые отмечены галочками, уже добавленные пропускаются. Папки запоминаются: в следующий раз хватит одного клика, чтобы подхватить новые проекты;
- кнопкой «Добавить проект»;
- перетаскиванием папки проекта в окно.

Язык, IDE, что ей открывать (`.sln` или папку с `settings.gradle`) и репозиторий лаунчер определяет сам по содержимому папки и `.git/config`.

Платформа определяется так:

- **Android**: `AndroidManifest.xml` или Android-плагин в `build.gradle`;
- **Windows**: `.csproj` с WPF, WinForms, `WinExe`, Avalonia, службой Windows или `-windows` во фреймворке; старый .NET Framework без `System.Web`; Electron в `package.json`;
- **Web**: `.csproj` на `Microsoft.NET.Sdk.Web` (даже если запускается как служба), `web.config`, `wwwroot`, React/Vue/Vite/Angular и Node-серверы в `package.json`.

Если в папке несколько частей (планшет + сервер), побеждает Android, потом Windows, потом Web. Поправить можно в окне проекта.

## Горячие клавиши

| Клавиши | Что делает |
| --- | --- |
| `Ctrl+K` / `Ctrl+F` | Поиск |
| `Enter` в поиске | Открыть первый найденный проект |
| `Esc` | Очистить поиск / закрыть окно |
| `Ctrl+N` | Добавить проект |

## Настройки

Кнопка с шестерёнкой.

- **Тема**: «как в системе», светлая или тёмная. Применяется сразу.
- **Папки с проектами**: общие папки для импорта.
- **Иконки**: свои картинки для платформ (Web, Windows, Android), GitHub, GitLab и языков вместо буквенных значков (PNG, SVG или ICO до 512 КБ). При загрузке прозрачные поля обрезаются, а картинка вписывается в квадрат с одинаковым отступом, поэтому все иконки выглядят одного размера. Логотипы в комплект не входят, загрузи свои.
- **GitLab**: адрес (например, `https://gitlab.yamz.local`) и токен со scope `read_api`. Для GitLab на самоподписанном сертификате есть галочка доверия. Если сертификат выдан корпоративным CA, который уже стоит в Windows, галочка не нужна.
- **GitHub**: токен необязателен, публичные репы работают и без него, но с лимитом 60 запросов в час. Для приватных нужен scope `repo`.
- **IDE**: пути находятся автоматически (Toolbox, стандартные папки, `vswhere` для Visual Studio). Если не нашлось, укажи `.exe` вручную.

Токены шифруются через DPAPI: расшифровать их может только твоя учётка на этом ПК. В интерфейс они обратно не отдаются.

## Где лежат данные

`%APPDATA%\project-launcher\`:

- `projects.json` — проекты и заметки;
- `settings.json` — настройки, токены в зашифрованном виде, размер окна.

Portable-exe можно переносить куда угодно, данные останутся на месте.

## Разработка

Нужен Node.js 22+.

```bash
npm install
npm run dev        # запуск с горячей перезагрузкой, DevTools по F12
npm run typecheck  # проверка типов
npm run dist       # сборка portable .exe в dist/
```

`npm run dist` запускай на Windows. Если сборка встала на скачивании Electron, значит, его блокирует корпоративный прокси; удобнее собирать через GitHub Actions (ниже).

## Сборка через GitHub Actions

Workflow `.github/workflows/build.yml` собирает exe на `windows-latest`:

- на каждый пуш в `main` exe появляется в артефактах прогона (вкладка Actions);
- на тег `v*` дополнительно создаётся релиз с exe:

```bash
git tag v0.1.0
git push origin v0.1.0
```

## Как устроено

```
src/
  shared/    типы и справочники (языки, IDE, хостинги), общие для всех частей
  main/      main-процесс Electron: доступ к диску, git, запуск IDE, API GitHub/GitLab
  preload/   мост между окном и main-процессом (window.api)
  renderer/  интерфейс на React
```

Окно не имеет доступа к Node: всё, что трогает диск, сеть или процессы, идёт через `window.api` в main-процесс. Запросы к GitHub/GitLab идут через сетевой стек Chromium (`net.fetch`), поэтому подхватывается системный прокси и сертификаты из хранилища Windows.

Свою иконку приложения положи в `build/icon.ico` (256×256), её подхватит electron-builder.
